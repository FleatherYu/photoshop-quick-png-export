## 1）背景与目标

在现有整图 PNG 导出功能上，增加将 Photoshop 当前选中的图层或组按顺序分别导出为 PNG 的能力，减少逐个隐藏图层、保存和编号的重复操作。

本方案基于工作区代码的只读核对。未修改文件、运行构建或测试，未连接或操作 Photoshop；下文的新增能力均为设计要求，实机行为的验证门槛另行标明。

## 2）范围：做什么 / 明确不做什么

### 2.1 导出对象与顺序

- 仅处理执行时 Photoshop 当前选中的图层和组，每个对象对应一张 PNG。
- 同时选中父组和其后代时，只保留父组；被去重的后代不计入跳过数量。
- 按图层面板从上到下排序，不按点击选择的先后排序。
- 对象身份以图层 ID 和层级位置识别，名称仅用于展示，允许重名。
- 明确选中的隐藏对象也导出：在副本中显示该对象；选中组时保留组内原有子层可见性与内部效果。

### 2.2 成像与尺寸

- 每次只显示一个有效选中对象，其他对象隐藏。
- 输出保留原文档画布尺寸和对象位置，不裁边、不缩放；空白区域透明。
- 组内依赖可以保留，例如剪贴关系与调整层的作用范围完全位于该组内部。
- 对象存在跨边界依赖时，提示并跳过，不自动带入其他对象。即使依赖对象也被选中，仍分别判断，不能默认合成同一张。
- 完全透明的最终成像跳过并提示，不占编号。
- 已识别的不支持情况属于“跳过”；读取、隔离、转换、透明检测或保存发生意外错误属于“失败”，立即停止。

### 2.3 命名、失败和重试

沿用 `前缀-编号.png`，与整图导出共用同一目录编号序列：

- 从同前缀现有文件的最大编号继续，不填补空缺。
- 位数仅决定最小补零宽度，超过宽度不截断。
- 中文文件名、百分号编码和扩展名大小写沿用现有规则。
- 只有成功保存并校验的项目进入成功清单；跳过项不占编号。
- 某项失败后立即停止，保留此前成功文件，返回成功清单、跳过清单、失败对象和未处理数量。
- 再次执行重新读取当前选择，并接续目录最大编号。**编号接续不等于任务断点续传**：仍被选中的已成功对象会再次导出。

### 2.4 界面与执行方式

保留整图导出入口，增加紧凑的“整图 / 选中图层”模式切换，共用前缀、位数和目录设置，默认仍为整图。

批量模式展示：

- 去重后的对象数量及名称列表；
- 宿主返回的预计文件名；
- “透明或依赖对象会跳过，实际编号以导出结果为准”的简短提示；
- 完成后的成功、跳过、失败及未处理数量，详情可展开。

执行期间显示“正在批量导出…”，禁用两个导出入口、模式与参数修改、目录选择和刷新操作，暂停状态轮询。收到结果后恢复。

首版不提供逐项进度和取消，也不提供批量导出全部图层、面板自行勾选对象、按图层名称命名、自动补依赖、自动重试失败项或新增格式。不得引入新依赖。

## 4）方案比较

### 4.1 多选读取方式

**核对结论：ExtendScript DOM 没有直接返回当前多选图层集合的属性；`doc.activeLayer` 只能表示活动图层，不能据此完成多选批量导出。**

推荐通过 ActionManager 读取活动文档描述符：使用 `executeActionGet`，文档引用为 `Dcmn / Ordn / Trgt`，读取 `stringIDToTypeID("targetLayers")` 对应列表，再解析图层引用。

该路径在机制上可行，但仓库没有现成实现或兼容性证据，本次也未实机运行，不能宣称已在 20.0.10 验证通过。

| 方案 | 优点 | 局限与结论 |
| --- | --- | --- |
| ActionManager 读取 `targetLayers` | 对应用户在 Photoshop 中的实际多选，符合需求 | 推荐；需验证单选属性缺失、无选择、有无背景层、嵌套组及索引映射。 |
| 仅使用 `doc.activeLayer` | 实现简单 | 只能导出一个对象。仅可在已确认当前确为单选时作为回退，不能在多选读取失败后静默使用。 |
| 面板列出顶层对象供勾选 | 不依赖 Photoshop 当前多选列表 | 改变用户操作方式，且遗漏嵌套对象。仅作后续替代方案，不纳入本次范围。 |

读取后立即将引用转换为稳定 ID 和层级路径，再按文档层树排序、去除已选祖先的后代。不得按名称匹配，也不得假定 `targetLayers` 列表顺序就是面板顺序。

图层索引会受背景层和组结构影响，不使用未经验证的固定偏移。复制后的 ID 是否保持也需验证；必要时使用未改结构前的层级路径建立源对象与副本对象映射。

多选读取失败应返回 `SELECTION_READ_FAILED` 并停止，不得退化为只导出最后一个图层。

### 4.2 图层隔离方式

| 方案 | 可行性与性能 | 结论 |
| --- | --- | --- |
| 整批复制一次，在副本中隐藏其他对象 | 只承担一次完整复制成本；每项重置可见性即可。保留层级与组内结构，但需防止上一项状态残留 | **推荐首版采用**，前提是验证隔离重置、转换和透明检测不会累积破坏副本。 |
| 在副本中删除其他对象 | 会破坏后续目标和依赖结构，难以复用；若配合撤销，又增加历史状态风险 | 不推荐。 |
| 每项从源文档重新复制，再隔离 | 每项状态干净，容易清理；大文档、多对象时复制和关闭成本高 | 作为共享副本方案无法可靠保持状态时的回退。 |

推荐流程是在不合并图层的完整副本中，保存初始可见性快照；每项均从快照恢复后重新隔离：

- 普通图层：只保留目标及必要祖先路径，隐藏路径上的其他分支。
- 组：显示目标组，组内子层恢复原有可见性，不能递归全部显示。
- 隐藏祖先可在副本中打开，以便显示选中的子对象；祖先效果或混合方式若影响独立成像，按依赖策略判断。
- 背景层、锁定对象的处理仅发生于副本；无法隔离时明确跳过或报错。

隐藏其他对象不会消除组混合模式、祖先蒙版、调整层及剪贴关系的影响。因此，“隐藏其他层”只是隔离手段，不能单独证明输出满足独立成像要求。

依赖检测应覆盖目标内部及祖先上下文。依赖边跨出目标边界时跳过；无法确定作用范围时保守跳过并说明原因。不能把所有调整层或所有组一律判为不支持。

### 4.3 透明判定

**结论：不采用 `layer.bounds == null` 判断全透明。**

`bounds` 表示边界数据，通常是四个坐标组成的 `UnitValue` 数组，并非透明度标志。空图层也不能假定返回 `null`；即使得到零面积边界，也不能覆盖蒙版全黑、不透明度为零、内容在画布外、组内全隐藏等情况。

推荐检测隔离后、最终输出状态下的画布合成 alpha，而非只检查目标层几何边界。具体检测操作必须先在 CC 2019 验证，当前仓库没有可直接复用的实现。

如果检测会改动选区、通道或图层，只能在副本中进行，并确保下一项恢复；需要破坏性合成时另建短生命周期探测副本，不在共享工作副本上合并。

独立验收：记录每个样例的输入、读取结果和成像结果。多选或透明检测未通过，不进入批量保存阶段。

### 阶段二：增加纯逻辑和接口契约

在 `jsx/core.jsx` 增加基于标准化对象数据的排序、祖先去重、批量命名计划和结果汇总逻辑；Photoshop DOM 与 ActionManager 操作留在宿主层。

建议新增接口：

- `QPE_call("previewSelectedLayers", argsJson)`
- `QPE_call("exportSelectedLayers", argsJson)`

参数复用 `prefix`、`digits`、`folder`。预览返回文档身份、对象列表、去重后数量、已知跳过原因和预计文件名。预览不执行完整透明探测时，必须明确标为预计。

执行时重新读取选择、校验文档与预览是否一致；发现文档或选择已变，返回 `SELECTION_CHANGED`，要求刷新。文档内容和目录仍以执行时状态为准。

结果至少包含：

| 字段 | 含义 |
| --- | --- |
| `ok`、`code`、`message` | 是否正常完成遍历，以及错误信息 |
| `completed` | 是否处理到本批末尾 |
| `successes` | 对象 ID、名称、实际编号、文件名、完整路径 |
| `skipped` | 对象 ID、名称、原因码及中文说明 |
| `failed` | 首个失败对象、阶段和错误；无失败时为空 |
| `unprocessedCount` | 停止后尚未处理数量 |
| `warnings`、`cleanupErrors` | 转换提示与清理异常 |

全部跳过属于完成但无输出，应显示“未导出，已跳过 N 项”，不显示普通成功文案。

独立验收：Node 测试验证纯逻辑与 ASCII JSON 契约。

### 阶段三：实现批量宿主事务

按以下顺序执行：

1. 校验文档、选择、前缀、位数、目录和可写性。
2. 保存源文档引用及全局对话框状态，设置宿主执行锁。
3. 创建不合并的工作副本，建立目标映射和可见性快照。
4. 逐项检测依赖、恢复并隔离、按已验证顺序转换和检测透明。
5. 对可导出项在保存前重新扫描目录，通过核心函数分配编号，再检查目标存在性。
6. 使用 `saveAs(..., asCopy=true)` 保存，验证文件存在且非零后记入成功清单。
7. 遇到意外失败立即停止。
8. 在 `finally` 中关闭本次副本、不保存，恢复活动源文档、对话框状态及执行锁，再返回汇总。

不得修改源文档可见性、活动图层、多选状态、选区、通道、历史、色彩模式或位深；不得在源文档合并图层。

清理失败不得伪装为成功。保存失败产生的可确认残缺文件，仅能清理本次新建的目标；绝不删除此前成功文件或执行前已有文件。

独立验收：宿主替身测试验证停止规则和各异常点的清理；真实 Photoshop 验证输出与源文档保护。

### 阶段四：接入面板与 mock

增加模式切换、数量与预计名称、结果折叠详情和刷新入口。busy 状态覆盖全部相关控件，并忽略执行前发出的过期预览或状态响应。

部分失败时仍展示成功清单并允许打开输出目录，不能直接沿用当前遇到 `ok:false` 即结束展示的单图逻辑。批量“复制路径”明确为复制成功文件路径列表。

mock 补齐成功、跳过、全部跳过、部分失败、选择变化和桥接错误场景。面板只展示宿主返回文件名，不自行生成批量编号。

独立验收：面板行为测试及真实 CEP 窄面板检查。

### 6.2 Photoshop CC 2019 20.0.10 / CEP 9 验收

1. **选择读取**：分别测试有背景层、无背景层、单选、多选、无选择、嵌套组、同名层和隐藏层；识别数量、身份及顺序全部正确。
2. **去重与组**：父组及后代同时选择只导出父组；组内隐藏子层保持隐藏，内部剪贴和调整效果按约定保留。
3. **独立成像**：用已知颜色和坐标的图层验证 PNG 不含其他对象，IHDR 尺寸与源画布一致，位置不变，空白区域 alpha 为零。
4. **透明跳过**：空图层、空组、不透明度为零、全遮蔽蒙版、画布外内容、全部子层隐藏均跳过且不占编号；带可见效果的对象不能误跳过。
5. **依赖检测**：外部剪贴基底、外部调整层、依赖外部背景的混合和祖先效果按支持矩阵提示跳过；内部自足的组正常输出。
6. **转换**：RGB/8 位、RGB/16 位及 CMYK 样例验证转换提示、输出透明与组结构处理；转换若破坏隔离前提，必须报错或明确跳过。
7. **部分失败**：受控注入第三项保存失败，确认前两张文件完整、后续未写入；再次执行从现有最大编号继续，已有文件哈希不变。
8. **源文档保护**：成功、全部跳过和失败后，对比源文档模式、位深、尺寸、层树、可见性、活动图层、多选、选区、通道、历史状态和保存状态，均不变；源文档重新活动，无本次临时文档残留。
9. **面板**：300×360 和 240×240、深浅主题下无横向溢出，按钮可达，长名称和大量结果可滚动查看；真实 CEP 完成一次多选导出。
10. **性能记录**：固定机器上，以 800×600、100 个普通图层、选中 20 层的样例连续运行三次，记录耗时和峰值内存；不得出现副本累积或漏导。

真实验收脚本继续保持纯 ASCII，并保留检测到其他用户文档时的 `SKIP` 保护。当前脚本在宿主检查前已清理并重建输出目录，且会按固定名称清理遗留测试文档；扩展时应将目录操作限制在专用测试目录，并避免仅凭名称关闭文档。`SKIP` 记录为未执行，不计为通过。

## 7）风险与回滚

| 风险 | 控制措施与回滚方式 |
| --- | --- |
| 多选索引映射错误导致导错对象 | 第一阶段验证背景层与嵌套组；按稳定身份映射，无法确定时停止。验证不通过则暂不开放批量入口。 |
| 隐藏其他对象后效果变化 | 建立依赖支持矩阵，跨边界或无法确认的情况跳过；不承诺与原画布所见完全一致。 |
| 共享副本状态污染 | 每项从初始快照恢复；若转换或探测无法可靠恢复，回退为每项复制。 |
| 转换丢失结构或透明 | 批量不能直接照搬现有整图转换流程；先验证转换顺序和输出 alpha，不满足时明确失败。 |
| 大文档耗时或内存不足 | 优先整批一次复制；清楚显示执行中，无虚假进度。首版不承诺固定耗时。 |
| 异常后副本残留 | `finally` 统一清理并恢复，清理失败单独返回；只处理本次持有引用的副本。 |
| 文件冲突 | 保存前重扫及存在性检查；现有检查与 `saveAs` 之间并非原子操作，首版不承诺对多个写入者同时操作同一编号序列提供互斥。 |
| Photoshop 崩溃或桥接结果丢失 | 已落盘文件保留；界面提示结果未知，要求检查目录，不能自动重试并假定上次未成功。 |

代码回滚以恢复上一版完整插件载荷为单位，包括匹配的面板文件与生成宿主；保留原有整图接口，避免批量故障影响整图使用。

回滚不删除用户已导出的 PNG，不重置目录编号，不通过撤销源文档修复状态。若尚未通过关键宿主验收，直接不发布批量入口。

## 8）剩余待确认问题

1. **CC 2019 中多选引用、背景层索引及副本对象映射是否稳定？**
   默认建议：先验证 `targetLayers` 主路径；仅在确认单选时使用 `activeLayer` 回退。多选读取失败明确报错，不静默降级，也不增加面板勾选流程。

2. **嵌套子对象的祖先蒙版、效果及复杂混合，首版支持到什么程度？**
   默认建议：只开放已验证可独立隔离的组合；跨出目标边界或无法确认的祖先影响均提示跳过，后续按样例扩充支持矩阵。

3. **最终合成 alpha 的可靠检测方式，以及转换与检测的正确顺序是什么？**
   默认建议：以画布内实际合成透明度为准，拒绝 `bounds == null` 判据；先验证不破坏工作副本的探测方式，必要时另建探测副本。无法可靠判定时返回检测失败并停止，不猜测为空或强行导出。
